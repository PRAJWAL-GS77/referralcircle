# Working Rules

- **Phase by phase**: Only do the phase named by the user. Keep each explanation SHORT (max 8 lines). Building is the priority.
- **Credit-efficient**: Do not re-read the whole repo, do not rewrite files that work, do not re-explain the brief, and do not create extra docs unless asked.
- **Beginner-friendly**: Provide exact terminal commands to run (Windows 11 PowerShell), exact `.env` values to fill, and instructions on where to get them.
- **Viva preparation**: Add brief comments only where the logic is non-obvious (cooldown, auth). Maintain a running `EXPLAIN.md` with 3-6 bullet points per phase explaining what was built, why, and how data flows.
- **Verification**: After each phase, run the app or tests, fix errors autonomously, and provide a 5-item checklist to verify manually. Then stop and wait.
- **Git & Security**: Never commit secrets. Keep `.env.example` files updated. Initialise git and make one commit per phase.
